# Trello風タスク管理アプリ 設計書

作成日：2026年9月26日

[要件定義書](requirements.md) で決めた機能を、どのように作るかをまとめる。

## 1. 技術構成

| 項目 | 内容 |
|---|---|
| 画面 | HTML + CSS + JavaScript（フレームワークは使わない） |
| ドラッグ＆ドロップ | [SortableJS](https://sortablejs.github.io/Sortable/)（CDN から読み込む） |
| データの保存 | ブラウザの localStorage |
| 通知 | ブラウザの Notification API |
| 動作確認 | VSCode の拡張機能「Live Server」でローカルサーバーを起動して開く |

ブラウザ通知はファイルを直接開いた状態（`file://`）では動かない場合があるため、Live Server を使って `http://localhost` で開く。

## 3. 画面設計

### 3.1 ボード画面

```
┌─────────────────────────────────────────────────┐
│  タスク管理                                      │
├───────────────┬───────────────┬─────────────────┤
│ 未着手         │ 作業中         │ 完了             │
│ ┌───────────┐ │ ┌───────────┐ │ ┌─────────────┐ │
│ │[高] 課題A  │ │ │[中] 資料作成│ │ │[低] 本を返す │ │
│ │ 9/30 20:00 │ │ │ 10/1 18:00 │ │ │             │ │
│ └───────────┘ │ └───────────┘ │ └─────────────┘ │
│ ＋ カードを追加 │ ＋ カードを追加 │ ＋ カードを追加   │
└───────────────┴───────────────┴─────────────────┘
```

- 3つのリストを横に並べる
- カードには優先度・タイトル・期限を表示する
- 優先度は色で区別する（高：赤、中：黄、低：灰）
- 期限切れのカードは、枠と期限の文字を赤色にする
- カードはドラッグで、別のリストへの移動と、リスト内の並び替えができる

### 3.2 カード編集ウィンドウ

「＋ カードを追加」またはカードをクリックすると開く。

```
┌──────────────────────────────┐
│ カードの編集                  │
│ タイトル（必須） [__________] │
│ 説明文         [__________]  │
│                [__________]  │
│ 優先度         [ 中 ▼ ]      │
│ 期限           [日付と時刻]   │
│                              │
│ [削除]        [キャンセル][保存] │
└──────────────────────────────┘
```

- HTML の `<dialog>` 要素で作る
- タイトルが空のときは保存できない
- 「削除」ボタンは既存のカードを編集するときだけ表示する
- 削除前に確認メッセージを表示する

## 4. データ設計

### 4.1 カードのデータ

```js
{
  id: "1727330000000",          // カードを区別する番号（作成時刻から自動で作る）
  title: "課題A",               // 必須
  description: "第3章の演習問題", // 任意。未入力は ""
  priority: "medium",           // "high" / "medium" / "low"。初期値は "medium"
  dueDate: "2026-09-30T20:00",  // 任意。未入力は ""
  list: "todo",                 // "todo"（未着手） / "doing"（作業中） / "done"（完了）
  notified: false               // 通知済みかどうか
}
```

### 4.2 保存方法

- すべてのカードを1つの配列にまとめ、localStorage の `tasks` というキーに JSON 形式で保存する
- 配列の中の順番が、リスト内での表示順になる
- カードを追加・編集・削除・移動するたびに保存する

## 5. 処理の流れ

| 操作 | 処理 |
|---|---|
| アプリを開く | localStorage からカードを読み込み、画面に表示する。通知の許可を求める |
| カードを追加 | 編集ウィンドウで入力 → 配列に追加 → 保存 → 再表示 |
| カードを編集 | 編集ウィンドウで変更 → 配列を更新 → 保存 → 再表示。期限を変えたら `notified` を `false` に戻す |
| カードを削除 | 確認メッセージ → 配列から削除 → 保存 → 再表示 |
| カードを移動・並び替え | ドラッグ後の画面の並びをもとに、各カードの `list` と配列の順番を更新 → 保存 |
| 通知の確認 | 30秒ごとに全カードを確認する。条件を満たしたカードの通知を表示し、`notified` を `true` にして保存する |
| 期限切れの確認 | 表示のたびと、30秒ごとの確認のときに判定して色を付ける |

### 5.1 通知・期限切れの条件

| 判定 | 条件 |
|---|---|
| 通知する | 期限が設定されている、期限の時刻を過ぎている、完了リストにない、まだ通知していない（`notified` が `false`） |
| 期限切れ表示 | 期限が設定されている、期限の時刻を過ぎている、完了リストにない |

ブラウザは、表示していないタブの処理を遅らせることがあるため、通知が最大1分程度遅れる場合がある。
