# 機能要件

作成日：2026年10月5日

[機能一覧](features.md) の各機能について、満たすべきルールをまとめる。画面の見た目は [画面要件](screens.md)、保存する項目は [データベース設計](../design/database.md) にまとめる。

## 1. 共通のルール

| 項目 | ルール |
| --- | --- |
| タイトルの文字数 | 1〜50文字。空白だけの入力は不可 |
| タイトルのエラーメッセージ | 空のとき「タイトルを入力してください」、50文字を超えたとき「タイトルは50文字以内で入力してください」 |
| 説明文の文字数 | 500文字まで。501文字目以降は入力できない |
| 優先度 | 高・中・低 の3段階。初期値は「中」 |
| 期限 | 日付と時刻。任意。過去の日時も設定でき、保存するとすぐに期限切れとして表示する |
| 完了したカード | 自動では消えない。不要になったら手動で削除する |
| 削除の取り消し | できない。そのため削除前に確認を表示する |
| カードの枚数 | 上限は設けない。100枚程度までを想定する |

## 2. 機能ごとのルール

### F-01 ボード表示

- 「未着手」「作業中」「完了」の3つのリストを、左からこの順に横に並べて表示する
- リストは3つで固定。追加・名前変更・削除はできない
- リスト名の横に、そのリストのカードの枚数を表示する
- アプリを開いたとき、保存されているカードをすべて表示する

### F-02 カード追加

- 各リストの「＋ カードを追加」から、そのリストにカードを追加する
- 入力できる項目はタイトル・説明文・優先度・期限。ルールは「1. 共通のルール」に従う
- タイトルが条件を満たさないときは保存せず、エラーメッセージを表示する
- 追加したカードは、そのリストの一番下に入る

### F-03 カード編集

- カードをクリックすると、タイトル・説明文・優先度・期限を変更できる
- 入力のルールとエラーの扱いは F-02 と同じ
- 「キャンセル」を押した場合は、変更内容を保存しない
- 期限を変更した場合は、新しい期限でもう一度リマインド通知を行う

### F-04 カード削除

- カードの編集中に「削除」を押すと、削除してよいか確認を表示する
- 確認で「OK」を押すと削除し、「キャンセル」を押すと編集に戻る
- 削除したカードは元に戻せない

### F-05 リスト間の移動

- カードをドラッグ＆ドロップして、別のリストへ移動できる
- 移動先のリストの中で、ドロップした位置に入る

### F-06 リスト内の並び替え

- カードをドラッグ＆ドロップして、同じリストの中で順番を入れ替えられる
- 並び順は保存され、次に開いたときも同じ順番で表示する

### F-07 データ保存

- カードの追加・編集・削除・移動・並び替えのたびに、自動で保存する。保存ボタンはない
- Chrome を閉じて再び開いても、カードの内容と並び順が残っている

### F-08 リマインド通知

- 初回利用時に、ブラウザの通知許可を求める
- 期限の時刻になったら、そのカードのタイトルをブラウザ通知で知らせる
- 完了リストにあるカード、期限がないカードは通知しない
- 1枚のカードにつき、通知は1回だけ。期限を変更した場合は、もう一度通知する
- 通知は、アプリのタブを開いている間だけ届く。最大1分程度遅れる場合がある
- 通知をクリックすると、アプリのタブを前面に表示する

### F-09 期限切れの表示

- 期限を過ぎていて、完了リスト以外にあるカードを「期限切れ」とする
- 期限切れのカードは、枠と期限の文字を赤色にする
- 完了リストに移すと、赤色の表示は消える

通知と期限切れの判定条件の詳細は、[データフロー](../design/data-flow.md) の「3. 通知・期限切れの判定」にまとめる。
