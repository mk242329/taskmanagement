# Trello風タスク管理アプリ 要件定義書

作成日：2026年9月26日

## 1. 概要

スクールの課題として、システム開発の流れを学ぶために、Trello風のタスク管理アプリを作る。完成後は、自分の仕事や勉強のタスク管理に実際に使う。

### 1.1 背景

スクールの課題として作成する。業務上の課題を解決することよりも、開発を通して学習することが主な目的である。

### 1.2 目的

- 要件定義・設計・実装・テストという、システム開発の流れを一通り経験する
- HTML・CSS・JavaScript の基礎を身につける
- 完成したアプリを、自分のタスク管理に実際に使う

### 1.3 利用者と用途

| 項目 | 内容 |
| --- | --- |
| 利用者 | 自分ひとり |
| 用途 | 仕事のタスク、勉強の進み具合の管理 |

### 1.4 利用シーン

1. 新しいタスクができたら、「未着手」にカードを追加する
2. 今日やる予定のタスクを確認する
3. 取りかかるタスクを「作業中」に移す
4. 終わったタスクを「完了」に移す

## 2. スコープ

最初のバージョンでは、カードの基本操作・並び替え・保存・リマインド通知だけを作る。

**今回作るもの**

- カードの追加・編集・削除
- カードのリスト間の移動と、リスト内の並び替え
- ブラウザへのデータ保存
- 期限時刻のブラウザ通知
- 期限切れカードの色分け

**今回作らないもの**

- ログイン、他の人との共有
- 担当者の割り当て
- 複数ボード
- リストの追加・名前変更
- ブラウザを閉じている間の通知（サーバーが必要になるため）

## 3. 機能要件

必須機能は9つ。すべて最初のバージョンで作る。

| No. | 機能 | 内容 |
| --- | --- | --- |
| F-01 | ボード表示 | 「未着手」「作業中」「完了」の3つのリストを横に並べて表示する |
| F-02 | カード追加 | 各リストにカードを追加する。タイトルは必須 |
| F-03 | カード編集 | タイトル・説明文・優先度・期限を後から変更する |
| F-04 | カード削除 | カードを削除する。削除前に確認を表示する |
| F-05 | リスト間の移動 | ドラッグ＆ドロップでカードを別のリストへ移動する |
| F-06 | リスト内の並び替え | ドラッグ＆ドロップで同じリスト内のカードの順番を入れ替える |
| F-07 | データ保存 | 変更のたびに自動で保存し、ブラウザを閉じても内容が残る |
| F-08 | リマインド通知 | 期限の時刻になると、ブラウザ通知を表示する |
| F-09 | 期限切れの表示 | 期限を過ぎた未完了のカードを赤色で目立たせる |

### 3.1 機能の詳細ルール

| 項目 | ルール |
| --- | --- |
| タイトルの文字数 | 1〜50文字。空白だけの入力は不可 |
| タイトルのエラーメッセージ | 空のとき「タイトルを入力してください」、50文字を超えたとき「タイトルは50文字以内で入力してください」 |
| 説明文の文字数 | 500文字まで |
| 過去の日時の期限 | 設定できる。保存するとすぐに期限切れとして表示する |
| 完了したカード | 自動では消えない。不要になったら手動で削除する |
| 削除の取り消し | できない。そのため削除前に確認を表示する |
| カードの枚数 | 上限は設けない。100枚程度までを想定する |

### 3.2 画面一覧とレイアウト

画面は5つ。見た目の模型は [画面レイアウト（モックアップ）](https://claude.ai/artifact/3G96XQhTYFqzfCbgry2K3h) で確認できる。

| 画面ID | 画面名 | 内容 |
| --- | --- | --- |
| SC-01 | ボード画面 | 3つのリストとカードを表示する。アプリを開くと最初に表示される |
| SC-02 | カード編集ウィンドウ | カードの追加と編集に使う。ボード画面の上に重ねて表示する |
| SC-03 | 削除確認ダイアログ | カードを削除してよいか確認する |
| SC-04 | 通知許可ダイアログ | ブラウザ通知を許可するか確認する。ブラウザ標準の画面 |
| SC-05 | リマインド通知 | 期限の時刻になったカードを知らせる。ブラウザ標準の画面 |

**SC-01 ボード画面**

```text
┌─────────────────────────────────────────────────┐
│  タスク管理                                      │
├───────────────┬───────────────┬─────────────────┤
│ 未着手 (3)     │ 作業中 (2)     │ 完了 (2)         │
│ ┌───────────┐ │ ┌───────────┐ │ ┌─────────────┐ │
│ │[高] 課題A  │ │ │[中] 資料作成│ │ │[低] 本を返す │ │
│ │ 9/30 20:00 │ │ │ 10/1 18:00 │ │ │             │ │
│ └───────────┘ │ └───────────┘ │ └─────────────┘ │
│ ＋ カードを追加 │ ＋ カードを追加 │ ＋ カードを追加   │
└───────────────┴───────────────┴─────────────────┘
```

- 「未着手」「作業中」「完了」の3つのリストを横に並べ、リスト名の横にカードの枚数を表示する
- カードには優先度・タイトル・期限を表示する。期限がないカードは期限を表示しない
- 優先度は色付きのラベルで表示する（高：赤、中：黄、低：灰）
- 期限切れのカードは、枠と期限の文字を赤色にする
- カードをクリックすると SC-02 を開く。「＋ カードを追加」を押しても SC-02 を開く

**SC-02 カード編集ウィンドウ**

```text
┌──────────────────────────────┐
│ カードの追加 / カードの編集    │
│ タイトル（必須） [__________] │
│ 説明文         [__________]  │
│                [__________]  │
│ 優先度         [ 中 ▼ ]      │
│ 期限           [日付と時刻]   │
│                              │
│ [削除]        [キャンセル][保存] │
└──────────────────────────────┘
```

- 追加のときは「カードの追加」、編集のときは「カードの編集」と見出しを表示する
- 「削除」ボタンは編集のときだけ表示する
- 入力に誤りがあるときは、タイトルの入力欄を赤い枠にし、その下にエラーメッセージを赤字で表示する

**SC-03 削除確認ダイアログ**

「このカードを削除しますか？」と表示し、「OK」と「キャンセル」のボタンを置く。

画面の移り変わりと各項目の詳細は、[設計書](design.md) の「2. 画面遷移図」「3. 画面レイアウト」にまとめる。

## 4. データ項目

カードは次の項目を持つ。リストは3つ固定のため、利用者が変更できる項目はない。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| タイトル | 必須 | タスクの名前 |
| 説明文 | 任意 | タスクの詳しい内容やメモ |
| 優先度 | 必須 | 高・中・低 の3段階。初期値は「中」 |
| 期限 | 任意 | 日付と時刻。リマインド通知にも使う |
| 所属リスト | 自動 | 未着手・作業中・完了 のどれか |
| 表示順 | 自動 | リスト内の並び順 |

### 4.1 ER図

1つのリストには0枚以上のカードが入り、1枚のカードは必ず1つのリストに入る。

```mermaid
erDiagram
    LIST["リスト"] ||--o{ CARD["カード"] : "含む"
    LIST["リスト"] {
        string id PK "リストID"
        string name "リスト名（未着手・作業中・完了）"
    }
    CARD["カード"] {
        string id PK "カードID"
        string title "タイトル"
        string description "説明文"
        string priority "優先度"
        datetime dueDate "期限"
        string listId FK "所属リスト"
    }
```

項目の型や保存方法などの詳細は、[設計書](design.md) の「4. ER図」にまとめる。

## 5. 非機能要件

サーバーを使わず、ブラウザだけで動くアプリにする。

| 項目 | 内容 |
| --- | --- |
| 対応ブラウザ | パソコン版 Google Chrome の最新版のみ。Safari、Edge では動作確認をしない |
| 対応画面 | パソコンのみ（画面の横幅 1024px 以上）。スマホは対象外 |
| 動作の速さ | 操作してから画面に反映されるまで1秒以内 |
| データの保存先 | ブラウザの localStorage |
| バックアップ | なし |
| セキュリティ | 個人情報やパスワードは入力しない前提とする |
| 通知の許可 | 初回利用時に、ブラウザの通知許可を求める |

## 6. 前提条件・制約条件

利用者は、次の条件を理解したうえで使う。

- ブラウザの閲覧履歴やサイトのデータを消すと、タスクもすべて消える
- 別のブラウザや別のパソコンでは、同じタスクを見られない
- リマインドを受け取るには、ブラウザ通知を許可する必要がある
- 通知は、アプリのタブを開いている間だけ届く。別のタブや別のアプリを使っていても届くが、最大1分程度遅れる場合がある
- パソコン側の通知設定（Mac の「集中モード」など）で通知を止めていると届かない

## 7. 受け入れ基準

次の3つを満たしたら完成とする。

1. 機能 F-01〜F-09 が、テスト仕様書の手順どおりに動くこと
2. Chrome を閉じて再び開いても、カードの内容が残っていること
3. テスト仕様書は、実装の前に作成すること
