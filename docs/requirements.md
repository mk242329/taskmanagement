# Trello風タスク管理アプリ 要件定義書

作成日：2026年9月26日
更新日：2026年10月6日

この文書は要件定義の全体をまとめる入口である。各テーマの詳細は「3. ドキュメント構成」のリンク先に書き、この文書には概要だけを書く。

## 1. 概要

スクールの課題として、システム開発の流れを学ぶために、Trello風のタスク管理アプリを作る。完成後は、自分の仕事や勉強のタスク管理に実際に使う。

### 1.1 背景

スクールの課題として作成する。業務上の課題を解決することよりも、開発を通して学習することが主な目的である。

### 1.2 目的

- 要件定義・設計・実装・テストという、システム開発の流れを一通り経験する
- Java・Spring Boot・React・PostgreSQL を使った Web アプリ開発の基礎を身につける
- 完成したアプリを、自分のタスク管理に実際に使う

### 1.3 利用者と用途

| 項目 | 内容 |
| --- | --- |
| 利用者 | 自分ひとり |
| 用途 | 仕事のタスク、勉強の進み具合の管理 |

### 1.4 利用シーン

1. 新しいタスクができたら、「未着手」にカードを追加する
2. 今日やる予定のタスクを確認する
3. 取りかかるタスクを「作業中」に移す
4. 終わったタスクを「完了」に移す

## 2. スコープ

最初のバージョンでは、カードの基本操作・並び替え・保存・リマインド通知だけを作る。

**今回作るもの**

- カードの追加・編集・削除
- カードのリスト間の移動と、リスト内の並び替え
- データベース（PostgreSQL）へのデータ保存
- 期限時刻のブラウザ通知
- 期限切れカードの色分け

**今回作らないもの**

- ログイン、他の人との共有
- 担当者の割り当て
- 複数ボード
- リストの追加・名前変更
- ブラウザを閉じている間の通知（Web Push などの仕組みが別に必要になるため）

## 4. 前提条件・制約条件

利用者は、次の条件を理解したうえで使う。

- アプリを使うときは、データベース・サーバー・画面の3つを起動しておく必要がある
- データは自分のパソコンの PostgreSQL に保存する。別のパソコンでは、同じタスクを見られない
- バックアップはないため、Docker のデータ（ボリューム）を消すと、タスクもすべて消える
- リマインドを受け取るには、ブラウザ通知を許可する必要がある
- 通知は、アプリのタブを開いている間だけ届く。別のタブや別のアプリを使っていても届くが、最大1分程度遅れる場合がある
- パソコン側の通知設定（Mac の「集中モード」など）で通知を止めていると届かない

## 5. 受け入れ基準

次の3つを満たしたら完成とする。

1. 機能 F-01〜F-11 が、テスト仕様書の手順どおりに動くこと
2. Chrome を閉じて再び開いても、カードの内容が残っていること
3. テスト仕様書は、実装の前に作成すること

## 6. 将来追加したい機能

最初のバージョンが完成したあと、必要に応じて追加する。

- 優先度や期限の順にカードを自動で並べ替える
- リストの追加・名前変更
- ラベル（色分け）
- 複数ボード
- コメント・チェックリスト
- ブラウザを閉じていても届く通知（Web Push などの仕組みが必要）
- ログイン・他の人との共有

## 7. 決定事項

- 技術構成：最初は HTML + CSS + JavaScript（ドラッグ＆ドロップは SortableJS）に決め、プロトタイプを作った。その後、バックエンドを Java + Spring Boot、フロントエンドを React、データベースを PostgreSQL に変更した。Next.js は使わない（2026年10月6日）
- 自動並べ替え：今回は作らない。将来追加したい機能に移す
- 期限切れの色分け：作る（F-09）
- 優先度：利用者が選ぶのをやめ、期限と時間厳守から自動で決める（F-10、2026年10月6日）
- チェックでの移動：カードのチェックボックスで、未着手→作業中→完了へ移せるようにする。ドラッグでの移動も残す（F-11、2026年10月6日）
